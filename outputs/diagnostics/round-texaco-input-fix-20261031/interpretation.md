|ΔT| 中位 178 K、最大 238 K；CO 多为负偏（本模型偏低 2–7 个百分点）。这与 P1.5-C 记录的锚定结论一致：即使把 Fortran 侧有开关的项全部切到兼容值，模式 F 仍有系统性温度偏低，主因是审计 B9 的固相焓 `Hf_coal` 基准。

**本轮没有为了缩小这个偏差去调水分、HHV 或热损。** 试过把 `Mt` 按 Fortran 的 `xmois=0.002` 改，I-1 立刻发散到 1818 K / cost 0.01，说明那不是修复而是拟合，已回退到论文的 4.53。

## 4. 决策记录

1. **几何取 Fortran 的 3.3 m，不取论文的 6.096 m。** 理由是验证对象就是该 Fortran 程序，用论文长度会让出口温度系统性低约 190 K，把两个不一致的来源混在一起。论文表头与程序自身的矛盾已写进 `reactor_geometry_note`。
2. **固定碳按 Fortran 的 `fc=65.0`（dmmf）换算。** 原始 JSON 的 proximate 块灰分 7.35 与 ultimate 的 15.53 矛盾，判定为母煤数据，不可直接用。
3. **水分取论文的 4.53%，不取 Fortran 的 0.002。** 取后者会修复数值但引入拟合。
4. **测试按收敛状态分支。** 未收敛的解不参与温度断言，但会把 residual cost 打进日志，回归时仍可见。

## 5. 影响面

- `CASE_TO_COAL_MAP` 中 Texaco I-* → Illinois residue、W-* → Wyodak、Exxon → DSP bottoms，其余条目（ShenYou、LuNan、Fluid_Coke、Paper_Case_6）未变。
- 华谊（`R52-C-75`）与 P2-A 轮次不使用这套校验数据，**不受本轮影响**。
- 依赖 `load_case_from_repo("Texaco_*")` 的历史脚本会拿到新的煤质与几何，数值会变；它们都是校验用途，不是论文轮次证据。
